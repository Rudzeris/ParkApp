# ParkApp — план реализации

Основан на `docs/DESIGN.md` и требованиях `docs/requirements/AutoPark.md`.

Оценки — в «человеко-днях» студенческой загрузки (≈3–4 ч в день), для ориентира, а не для обязательств.

Порядок этапов подчинён одному принципу: **сначала то, на что опираются остальные** (машина, вложения, общий каркас UI), потом справочники, потом генерация документов, в конце — сервер.

---

## Обзор

| Этап | Содержание | Оценка | Статус |
|---|---|---|---|
| 0 | Каркас: команды, диалоги, вложения, техдолг | 2 д | **частично сделано** (в прототипе штрафов) |
| 1 | Машина и люди: карточка, редактирование, сканы | 3 д | **поля и чтение готовы** |
| 2 | Штрафы: доведение прототипа | 1 д | **прототип готов** |
| 3 | Путевые листы | 2 д | **печать готова**, учёт рейсов — план |
| 4 | Страховки + контроль сроков | 2 д | план |
| 5 | Наряд на выход техники | 2 д | **прототип готов** |
| 6 | ТО: заявки + акт Ф-12 в Word | 4 д | план (движок шаблонов Word готов) |
| 7 | Отчёты и печать | 2 д | план |
| 8 | Переезд на сервер (БД + сеть) | 5 д | будущее |

## Риски

| Риск | Влияние | Что делаем |
|---|---|---|
| Формула наработки (О-2) не согласована | этап 6 стоит | запросить норматив до начала этапа 6; заготовить интерфейс `IMaxOdometerCalculator` |
| JSON не тянет объём / нужен второй ПК | переделка хранения | слои уже разделены, меняется только `Infrastructure` |
| Строковый водитель не сходится в отчётах (опечатки в ФИО) | отчёты по водителям кривые | автодополнение из введённых значений уже в прототипе; при росте — справочник |
| Файл таблицы открыт в Excel во время сохранения | правка не сохраняется | приложение показывает «закройте файл и повторите»; запись атомарная, прежняя версия остаётся в `.bak` |
| Двое работают с одной папкой одновременно | правки одного затираются | до перехода на БД — работа по очереди; критерии перехода в DESIGN §5.4 |
| Столбцы в реальной таблице названы иначе, чем ожидает код | машины не прочитаются | шапки сверены с настоящими книгами; проверки `tools/cars-check.py` и `tools/fines-check.py` гоняются по ним |
| В книгу дописывают строки и столбцы, о которых приложение не знает | перезапись их съедает | строки без номера постановления и ячейки правее шапки возвращаются на место вместе с формулами |
| Старый формат csproj — файлы забываются в сборке | «у меня не компилируется» | правило: новый файл = запись в `.csproj` в том же коммите |
| Сканы разрастаются на диске | место на ПК | хранить относительные пути, вынести `Scans/` на шару на этапе 8 |
| Шаблон Word правят и ломают плейсхолдеры | документ печатается с `{{ЦЕЛЬ}}` вместо значения | незаполненные плейсхолдеры вычищаются или заменяются прочерком; оригиналы форм и сборка шаблонов лежат в репозитории, шаблон всегда можно пересобрать |
| В подсказках наряда не хватает нужного значения | приходится набирать целиком | графа и так вписывается руками; набранное попадает в подсказки со следующего открытия окна |
| Группа машины в таблице названа иначе, чем группы наряда | машина печатается отдельной группой | значения ведутся справочным листом «Куда относится» в файле машин; незнакомая группа не теряется, а встаёт после известных |
| Перезапись книги съедает формулы-ссылки | связь между листами превращается в разовый текст | формула читается и возвращается на место вместе с посчитанным значением (`tools/xlsx-check.py`) |
| Реквизиты печати не заполнены | наряд с пустыми подписями | лист «Реквизиты» создаётся с названиями параметров; проверку при печати добавить после первого реального использования |
| Проект ни разу не собирался | «у меня не компилируется» | собрать в Visual Studio первым делом (этап 0); форматы файлов уже проверены сторонними разборщиками |
