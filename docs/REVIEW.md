# ParkApp — разбор изъянов

**Дата:** 2 октября 2026
**Что проверялось:** ветка `claude/kind-tesla-09l8qb` поверх `main` (все 11 невлитых коммитов: наряд, путевые листы, настоящие книги, вкладки, поиск).

---

## Как проверялось

До этого разбора проект **ни разу не собирался компилятором** — среды с Windows не было. Теперь есть два инструмента, и оба лежат в репозитории:

| Инструмент | Что делает | Запуск |
|---|---|---|
| `tools/build` | собирает приложение так же, как Visual Studio: .NET Framework 4.8, **C# 7.3**, полная компиляция XAML. Работает на Linux | `tools/build/build.sh` |
| `tools/realrun` | запускает **настоящий код** слоёв Domain, Application и Infrastructure на книгах, повторяющих рабочие файлы заказчика: 23 стиля, формулы, объединённые ячейки, второй лист, повтор номера | `python3 tools/realrun/make_fixtures.py`, затем `dotnet run --project tools/realrun -- tools/realrun` |

Python-проверки в `tools/*-check.py` повторяли логику по памяти. `tools/realrun` гоняет сам C#-код — поэтому нашёл то, чего они не видели.

**Сборка: 0 ошибок, 0 предупреждений.** Код компилируется как C# 7.3 под .NET Framework 4.8, разметка XAML — тоже (оба прохода, включая разрешение типов и обработчиков событий). Остальные находки — то, чего компилятор не видит.

Каждая находка, помеченная **«воспроизводится»**, — это проваленная проверка в `tools/realrun`. Исправленная находка превращает её в «ok».

## Критично: потеря и порча данных

### 1. После сохранения Excel считает книгу постановлений повреждённой — воспроизводится

При записи книга собирается заново, и таблица стилей заменяется своей — из 5 стилей. А ячейки, которые приложение не понимает (примечания правее шапки и т.п.), сохраняют **старые номера стилей**. В рабочей книге заказчика таких стилей 23, и примечания в `L:N` ссылаются на стиль № 21. После первого же сохранения:

```
номера стилей ячеек в пределах таблицы стилей: наибольший 21 при 5 стилях
```

Ссылка на несуществующий стиль — повреждение файла. Excel при открытии предложит «восстановить содержимое».

Даже там, где номер в пределах, он означает уже **другой** стиль: стиль 1 был «текст», а стал «дата».

**Направление:** не собирать книгу заново, а менять в исходном пакете только лист с данными (и общие строки), оставляя `styles.xml` и всё остальное как было. Либо переносить нужные стили из исходной таблицы в новую и перенумеровывать ссылки.

### 2. Другие листы книги постановлений удаляются — воспроизводится

`XlsxWriter.Write(path, sheetName, …)` пишет книгу из одного листа. Если в файле есть ещё листы — сверка, черновики, что угодно, — они исчезают при первом сохранении, без предупреждения.

```
другие листы книги не удалены: было TEST, Сверка с ГИБДД; стало TEST
```

**Направление:** то же, что в п. 1 — переписывать только свой лист.

### 3. Запись с повторным номером постановления удаляется — воспроизводится

Номер постановления — ключ записи. Если в книге две строки с одним номером (ошибка ввода, повторная запись), обе читаются и обе видны в списке. Но при сохранении `Ordered()` пропускает все повторы ключа — вторая строка **молча исчезает из книги**.

Попутно: «Изменить» на второй строке откроет первую — поиск идёт по номеру.

**Направление:** ключом строки на время сеанса должен быть её номер в книге, а не номер постановления; повтор номера — предупреждение, а не повод выбросить строку.

### 4. Резервная копия хранит только один шаг

`.bak` перезаписывается при каждом сохранении. После второго сохранения состояние до правок приложения уже не восстановить — то есть удалённый лист из п. 2 пропадает безвозвратно.

**Направление:** хранить несколько копий с датой (`Штрафы 2026-10-02 1714.xlsx`) или хотя бы копию «до первой правки приложением». Пункт «резервное копирование при старте» уже есть в плане.

## Серьёзно: неверные данные на экране и в документах

### 5. Должностные лица нумеруются по порядку, а не по столбцу «№» — воспроизводится

`SheetTable.Normalize` выбрасывает из заголовков символ «№». Заголовок, состоящий из одного «№», превращается в пустую строку и не находится никогда. Тогда номер человеку даётся по порядку заполненных строк.

На листе «Должностные лица» заранее пронумерованы 44 строки, а заполнены выборочно. Человек в строке «№ 7» получит номер 1, если строки выше пустые. Машина с «№ Д л» = 7 найдёт **не того человека** — или никого. Это видно:

- в списке машин, графа «Должностное лицо»;
- в наряде, графа «В чьё распоряжение» — она подставляется по этому же номеру и **печатается**.

```
номер берётся из столбца «№», а не по порядку  — ПЛОХО: человек из строки «№ 2» получил номер 1
```

**Направление:** не выбрасывать «№», когда без него от заголовка ничего не остаётся. Заодно — см. п. 13.

### 6. Переключение вкладок теряет несохранённый наряд и сбрасывает отбор

`TabControl` в WPF держит на экране только выбранную вкладку: при переключении содержимое строится заново, и `DispatchView` / `FinesView` создаются новыми экземплярами. Защита «загрузить один раз» стоит в экземпляре вида — у нового экземпляра она снова пуста, и вызывается `InitializeAsync()`:

- **наряд:** `LoadAsync()` перечитывает план с диска — отметки «в наряд», время, цель и маршрут, не сохранённые до переключения, **пропадают**;
- **книга постановлений:** книга перечитывается целиком, отбор по машине сбрасывается на «все машины».

То же при перетаскивании вкладки в отдельное окно. Комментарий в коде («перечитывать книгу заново незачем») неверен.

*Проверено по устройству `TabControl`; сам WPF в этой среде не запускается.*

**Направление:** «загружено ли» должна помнить модель, а не вид. Либо держать содержимое всех вкладок живым (известный приём — `TabControl` со своим шаблоном, где каждая вкладка в своём `ContentPresenter`).

### 7. Оформление книги постановлений теряется — воспроизводится частично

Перезапись книги с нуля теряет:

- **объединённые ячейки** — `L3:N3`, `L4:N4` (воспроизводится);
- **ширины столбцов** — пишутся свои;
- **перенос текста** в графе оплаты: исходный стиль 22 с `wrapText` заменяется стилем по умолчанию, и двухстрочная запись «Оплата … / ИД платежа …» показывается в одну строку;
- параметры печати, высоты строк, закрепление областей, условное форматирование, проверка данных, примечания к ячейкам.

Дизайн-документ (§6.3) обещает, что чужие столбцы возвращаются «вместе с типом и оформлением ячейки». На деле — нет, см. п. 1.

**Направление:** то же, что в п. 1.

## Средне

### 8. Крестик закрывает редактор постановления без вопроса

У редактора нет понятия «есть несохранённые правки», а крестик вкладки закрывает её сразу. Набрал запись, промахнулся по крестику — запись пропала.

### 9. Два редактора одной записи — побеждает последнее сохранение

Редакторов можно открыть сколько угодно, в том числе на одну и ту же запись. Сохранили оба — правки первого молча затёрты вторым.

**Направление:** открывать ту же запись в уже открытой вкладке — ключом вкладки сделать номер постановления, а не случайный `Guid`.

### 10. Формула «ОБЩАЯ СУММА» перестанет считать новые записи

В книге `=SUM(G3:G110)`. Приложение дописывает записи в конец, а диапазон не трогает. После 108-й записи итог в Excel начнёт расходиться с книгой, без всякого предупреждения. Итог в самом приложении не страдает — он считается заново.

**Направление:** при дописывании за пределы диапазона расширять его; или предупреждать.

Попутно: после правок в ячейке остаётся прежнее посчитанное значение — в прогоне 4500 при настоящей сумме 5250, — а флага «пересчитать при открытии» (`fullCalcOnLoad`) приложение не ставит. Пересчитает ли Excel сам — зависит от версии; надёжнее флаг поставить.

### 11. Настройки и данные по умолчанию — рядом с программой

`Настройки.xml` и папки данных по умолчанию лежат в папке программы. Если программу поставить в `C:\Program Files`, обычный пользователь туда не пишет: настройки не сохранятся (сообщение будет), а файлы-образцы при первом запуске не создадутся.

**Направление:** настройки — в `%AppData%\ParkApp`; данные — путь, выбранный при первом запуске.

### 12. Нет общего перехвата необработанных исключений

`DispatcherUnhandledException` не обработан. Любая непредусмотренная ошибка закрывает приложение без сообщения. Пункт есть в плане, но с появлением вкладок и окон он стал важнее: теперь падение уносит все открытые редакторы.

### 13. Список машин не использует готовое имя из ячейки

Графа «Должностное лицо» в таблице машин — формула-ссылка на лист людей, и приложение уже читает её значение (`Car.OfficialName`). Но список машин показывает человека, найденного **по номеру** через справочник (`CarRowViewModel.OfficialText`). Готовое и правильное значение из ячейки не используется — а поиск по номеру сломан (п. 5).

**Направление:** показывать `OfficialName`, а справочник людей использовать там, где нужны отдельные поля.

## Мелко

14. **Текстовые даты становятся датами Excel.** В книге «Дата привлечения» записана текстом («11.01.2026»). После первого сохранения весь столбец — настоящие даты. Скорее польза, но это изменение чужой книги, о котором заказчик не знает.
15. **`packages.config` и `.csproj` расходятся:** `Xceed.Document.NET` объявлен как 6.0, а ссылка в проекте — 2.2.0 из папки `DocX`. Сам `DocX` больше не используется — документы заполняет свой `WordTemplate`. Пакеты можно убрать.
16. **Перенесённая вкладка держит старое окно в памяти:** при переносе подписка старого набора вкладок на `Closing` не снимается.
17. **Закрыть главное окно при открытых оторванных можно** — и после этого разделы открыть негде, а приложение продолжает работать.
18. **Документация устарела:** §12 числит техдолгом `JsonCarRepository`, которого давно нет; §6.3 обещает сохранение оформления (п. 7).
